# Grounding brief

## Outcome lock

Update only an existing server-bound pending intent during coupon application. Browser intent IDs are non-authoritative.

## Non-goals and sibling fence

Intent creation is excluded. No sibling owner selects zero-total behavior.

## Viable minimal paths

For a zero amount, either keep the pending intent unchanged or cancel it. Both preserve the local coupon result but differ in provider state and recovery behavior.

## Open K2

Whether a zero amount leaves the pending intent unchanged or cancels it.
