# OKR

Source: [Loop Engineering Methodology Skill Generator](https://loopengineering.app/methodology-skill-generator/)

## Definition

Set a qualitative objective and a small number of measurable key results.

## Fit

- Best when a team needs direction plus measurable outcomes.
- Avoid when the task is a small operational checklist without a broader
  objective.

## Principles

- Keep the objective memorable.
- Make key results measurable.
- Limit the number of key results.
- Review progress on an explicit cadence.

## Steps

1. Write the objective.
2. Add two to four key results.
3. Confirm that each key result measures an outcome.
4. Name the review cadence.
5. Define what changes when progress is weak.

## Quality questions

- Is the objective understandable without a metric?
- Are key results measurable outcomes?
- Is the number of key results limited?
- Is the review cadence explicit?

## Stop

Stop when the objective, key results, and review cadence are reviewable. Use a
direct checklist for one small operational task. Stop and ask for human help
if the task does not fit OKR, required context is missing, or validation cannot
be satisfied without guessing.
