## Topics Resolved

- `risk-calibrated-pr-review` is the canonical hostile gate for an opened PR.
  `adversarial-diff-review` remains available for an explicitly requested
  branch/worktree boundary, especially before a PR exists.
- Review trust is author-independent: treat implementation claims, tests, and
  confident code as unverified. Do not infer quality from seniority, identity,
  tooling, or authorship.
- Review depth and priority derive from concrete consequences and activation,
  not diff size, a subsystem label, or an explicitly supplied criticality.
- The current `adversarial-spec-review` and `spec-readiness` rewrites were
  tested against historical and synthetic cases before PR #6 review. No request
  is currently open to redesign the other workflow skills.

## Topics Open

- **Exact PR basis:** The current skill records base/head initially but
  explicitly re-resolves only head before reporting. It also does not explicitly
  require local inspected files to come from a clean checkout at the PR head.
  This was found by contract inspection; base-advance, retarget, and dirty
  checkout behavior have not yet been reproduced.
- **First-review completeness:** The result gate permits `FAIL` while coverage
  remains partial. It is unresolved whether the complete-discovery rules already
  prevent premature stopping strongly enough, or whether an agent can find one
  P1 and defer other independent P1 families. No controlled two-independent-P1
  run has tested this.
- **Tier fixture reproducibility:** Validation rows demand `critical` for a
  required startup dependency and at least `high` for dormant database support
  without stating all reach, recovery, and consequence facts. This textual
  tension has not been blind-tested using only the fixture wording.

## Open Design Questions

## Key Decisions

  junior/senior or tool-based trust labels / Because: the user clarified that
  the writer's identity is irrelevant; plausible code may still rest on false
  assumptions.
- Selected: consequence-calibrated depth / Rejected: averaging every change at
  one review intensity / Because: the user stated that the effect of an error,
  including whether a tiny edit can activate payment or other critical
  behavior, matters more than its visual size.
- Selected: `risk-calibrated-pr-review` as the opened-PR gate / Rejected:
  `adversarial-diff-review` as the canonical opened-PR gate / Because: the
  existing review felt general and insufficiently accountable for downstream
  consequences.
- Selected: ship the new skill and workflow/catalog integration in this repo /
  Rejected: leave the proposal unshipped / Because: the user explicitly
  approved shipping after the design and comparison work.

## Gotchas for Next Session

- A real-PR run with rich repository context does not test whether a sparse
  validation fixture is independently reproducible.
- A definite finding can correctly make the verdict `FAIL` even with partial
  coverage; the unresolved issue is whether all other independently attackable
  P0/P1 families must be completed before stopping.
- Exact-head stability does not imply exact-PR-boundary stability: the base can
  advance or be retargeted while head remains unchanged.
- The repository is the source of truth. Do not update global skill copies.
